# 최후의 섬 — 멀티플레이 (최대 4인)

기존 싱글 프로토타입을 바탕으로 만든 최대 4인 멀티플레이 배틀로얄입니다. 섬에는 항상 100명이 내립니다.

| 플레이어 | 봇 |
|---|---|
| 1명 (혼자 하기) | 99명 (기존 게임과 동일) |
| 2명 | 98명 |
| 3명 | 97명 |
| 4명 | 96명 |

## 폴더 구성

```
server.js          Node 서버: 정적 파일 제공 + /ws 웹소켓(방 관리, 메시지 중계, 방장 승계)
public/index.html  게임 본체 (기존 게임 + 멀티플레이 동기화 코드)
public/lobby.js    첫 화면: 닉네임, 혼자 하기, 방 만들기/참가
test-server.js     서버 점검 스크립트 (1~4명 봇 수, 중계, 정원 초과 거절)
render.yaml        Render 배포 설정 (Blueprint)
package.json       의존성(ws)과 실행 스크립트
```

## 로컬에서 테스트하기

필요한 것: Node.js 18 이상, 인터넷 연결(Three.js와 글꼴을 CDN에서 불러옵니다).

```bash
npm install
```

```bash
npm start
```

브라우저에서 `http://localhost:3000` 을 엽니다.

### 혼자 테스트하기 (창 여러 개)
1. 첫 번째 창에서 닉네임을 입력하고 **방 만들기** → 5자리 방 코드가 나옵니다.
2. 두 번째 창(또는 시크릿 창)에서 다른 닉네임으로 코드를 입력하고 **참가**합니다. 방 목록의 **참가** 버튼을 눌러도 됩니다.
3. 방장 창에서 **게임 시작**을 누르면 모든 창이 같은 섬을 만들고, 모두 준비되면 동시에 수송기에 탑승합니다.

팁: 탭보다는 **창을 나란히** 띄우면 두 화면을 동시에 볼 수 있습니다. 뒤로 간 탭도 백그라운드 타이머로 시뮬레이션이 계속 돌아가므로 탭으로 테스트해도 게임은 멈추지 않습니다. 같은 브라우저에서 여러 탭을 써도 닉네임은 탭마다 따로 저장됩니다.

### 같은 와이파이의 다른 기기로 테스트하기
서버를 켠 컴퓨터의 내부 IP(예: `192.168.0.12`)를 확인한 뒤 다른 기기에서 `http://192.168.0.12:3000` 으로 접속합니다. 맥은 `ipconfig getifaddr en0` 으로 IP를 확인할 수 있습니다. 방화벽이 막으면 3000번 포트를 허용하세요.

### 서버 점검 스크립트
서버를 켠 상태에서 다른 터미널에서 실행합니다.

```bash
node test-server.js
```

1~4명일 때 봇 수(99/98/97/96), 시작 신호, 메시지 중계, 5번째 참가 거절을 확인합니다.

### 상태 들여다보기 (개발용)
주소 뒤에 `?debug` 를 붙여 열면(`http://localhost:3000/?debug`) 개발자 도구 콘솔에서 `__islandDebug` 로 플레이어·봇·차량 상태를 볼 수 있습니다.

## Render에 배포하기

1. 이 폴더를 GitHub 저장소에 올립니다 (`node_modules` 는 `.gitignore` 로 제외됨).
2. [Render 대시보드](https://dashboard.render.com)에서 **New → Blueprint** 를 고르고 저장소를 연결합니다. 루트의 `render.yaml` 을 읽어 웹 서비스를 만듭니다.
   - Blueprint 대신 **New → Web Service** 로 만들 때는 Runtime `Node`, Build Command `npm install`, Start Command `node server.js`, Health Check Path `/healthz` 로 설정하면 됩니다.
3. 배포가 끝나면 `https://<서비스이름>.onrender.com` 으로 접속해 친구에게 주소와 방 코드를 알려주면 됩니다. https에서는 자동으로 `wss://` 웹소켓을 씁니다.

참고
- 포트는 Render가 넣어주는 `PORT` 환경 변수를 그대로 씁니다.
- 무료 플랜은 15분 동안 접속이 없으면 잠들고, 첫 접속 때 깨어나는 데 30초~1분 정도 걸립니다. 게임 중에는 웹소켓 연결이 유지되므로 잠들지 않습니다.
- `render.yaml` 의 `region` 은 `singapore` 로 되어 있습니다(한국에서 가장 가까운 편). 바꾸려면 `oregon`, `frankfurt` 등으로 수정하세요.

## 멀티플레이 동작 방식

- **같은 섬**: 방장이 시작하면 서버가 시드를 정해 모두에게 보냅니다. 월드 생성 동안에는 시드 기반 난수만 쓰므로 모든 참가자가 똑같은 지형·건물·상자·차량·봇을 만듭니다. 터치 기기가 한 명이라도 있으면 모두 가벼운 월드 설정으로 맞춥니다. 생성이 끝나면 참가자끼리 월드 해시를 비교해 다르면 경고를 띄웁니다.
- **방장(호스트)**: 봇 AI, 자기장, 보급 투하, 차량 내구도를 계산하고 초당 10회 스냅샷을 보냅니다. 봇은 가장 가까운 사람 플레이어(방장 또는 참가자)를 노립니다.
- **참가자**: 봇을 스냅샷대로 부드럽게 보간해 보여주고, 봇에게 준 피해는 방장에게 보내 판정받습니다.
- **모두**: 자기 캐릭터와 자기가 운전하는 차량은 직접 시뮬레이션해 초당 15회 보냅니다. 총에 맞았는지는 쏜 사람 화면 기준으로 판정해 맞은 사람에게 전달합니다.
- **상자**: 내용물이 (시드 + 상자 번호)로 정해져서 누가 열어도 같은 아이템이 나옵니다. 줍기·버리기·사망 가방도 모두 동기화됩니다.
- **방장이 나가면**: 서버가 다음 참가자를 방장으로 정하고, 그 사람이 봇 진행을 이어받습니다.
- **서버 연결이 끊기면**: 게임이 멈추지 않고 혼자서 계속 진행됩니다.

## 게임 방식

- **개인전**: 플레이어끼리도 적입니다. 마지막 1명이 승리합니다. 다른 플레이어의 이름표는 가까이에서 보일 때만 표시됩니다.
- **협동전**: 플레이어끼리 한 팀입니다. 서로 피해를 주지 않고, 이름표와 미니맵 위치가 항상 보입니다. 봇을 모두 쓰러뜨리면 살아남은 플레이어 모두 승리합니다.

죽은 뒤에는 **관전하기**로 살아 있는 다른 플레이어를 볼 수 있고, **방으로 돌아가기**를 누르면 같은 방으로 다시 들어가 다음 판을 기다립니다.

## 알려진 한계

- 서버는 메시지를 중계만 하고 판정은 각 브라우저가 하므로, 조작된 클라이언트의 부정행위는 막지 못합니다 (친구끼리 하는 용도).
- 진행 중인 판에는 중간 참가할 수 없습니다. 방에 들어가 있으면 판이 끝난 뒤 함께 시작할 수 있습니다.
- 두 사람이 거의 동시에 같은 아이템을 주우면 둘 다 얻을 수 있고, 운전자가 없는 차를 밀었을 때 위치가 사람마다 조금 다를 수 있습니다.
